# 本机复用的理论成本收益

结论：对于反复出现、输入输出稳定、可独立验收的操作，ATR 有条件地降低 Agent 的重复工作成本，值得以小工具面接入日常客户端；一次性任务通常不能保证收益。本次没有运行工作量实验、真实模型调用或账单对照，不能给出实测节省比例。

## 收益从哪里来

直接路线每次可能需要理解任务、生成命令或脚本、调试及读回输出。复用路线把稳定的过程固化一次，之后只检索、填参数、执行和读结果。收益不是来自把 Python 换个进程运行，而是减少重复的规划、生成和失败修复。输入和必要输出仍然要付出相应上下文成本。

设单次直接路线期望成本为 D，复用路线为 R（包括工具调用、输入输出、预期失败重试），一次性创建/独立验收/集成成本为 F，会话工具定义与 hook 总开销为 H，后续维护成本为 U。N 次成功完成的净节省为：

`G(N) = N × (D − R) − F − H − U`

只有 D > R，且 `N > (F + H + U) / (D − R)`，才得到严格正收益。成本可以用加权 Token、金额、等待时间或人工时间表示，但必须统一单位；输入、缓存输入和输出的价格不同，不能简单把所有 Token 相加当作金额。

纯假设例子：创建与验收12,000个加权成本单位，定义和 hook 分摊2,000，直接执行每次1,800，复用300，则需超过14,000/1,500≈9.33次，即第10次起理论净收益为正。这不是本机测量结果，也不是价格承诺。

现实还会有未命中。若 M 次请求中命中概率为 p，每次 hook 开销为 h，未命中检索代价为 q，S 个会话的定义开销为 s，可写成：

`G = M × p × (D − R) − F − S × s − M × h − M × (1 − p) × q − U`

因此低命中率、频繁变化的工具、错误复用、庞大工具定义或大结果返回都可能让收益为负。质量要求相同才可比较成本；错误答案更便宜不算收益。

## 本次接入怎样控制额外成本

MCP 暴露少量入口，具体工具 schema 按检索命中返回，单次最多3个。hook 无模型调用、无网络，只读本地已验收元数据；未匹配返回空对象，匹配时仅附短提示，不要求每个请求都检索。内置 JSON/CSV/文本操作已由宿主提供实现和独立案例，用户无需为这些操作重复生成程序。候选代码不会自动变成本机受信代码。

微小的一次性操作、已知更短的原生命令、无法稳定验收的研究判断，可继续使用客户端现有工具。MCP/hook 本身不能强制模型每次作最优选择，理论价值并不证明客户端会自动达到最优命中率。

## 无镜像的收益与代价

本机接入减少镜像下载、Docker 服务依赖及容器冷启动；它本身不减少语言模型 Token，也不等价于隔离沙盒。Native 模式只执行操作者明确受信的纯 Python bundle，提供超时、取消、输出上限和进程清理；不提供容器级 CPU/内存/PID/网络或文件系统隔离。独立案例覆盖有限行为，无法证明程序无后门。未知模型代码需要先经人工审核或继续使用原有隔离后端。

既有 Headroom 等上下文工具负责的压缩收益不计入 ATR 的收益。后续只有真实工作产生的成本与质量记录，才能检验这些条件是否在用户场景成立；本次遵循用户要求，只交付代码与理论分析。
