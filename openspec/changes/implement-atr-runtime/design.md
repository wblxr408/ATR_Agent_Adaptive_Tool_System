# Design

## Context

参见 proposal.md。现有内容仅 docs/ATR_Agent_Adaptive_Tool_System_Plan_v1.md。宿主 Windows，有 Python 3.12、uv、Docker CLI；Docker 引擎可用性须在真实执行验收中确认。无既有 Agent、模型供应商或任务账单。

## Goals / Non-Goals

**Goals:** 落实全部 v1 控制路径，提供可嵌入 Python API、JSONL 五接口、CLI 和可复现示例。

**Non-Goals:** 自动发布、私自调用付费模型、制造真实40任务样本或宣称已实现15%节省。

## Decisions

1. Pydantic 严格边界与 Draft 2020-12 JSON Schema；SQLite WAL 事务维护元数据、幂等与版本指针；FTS5 独立索引兼顾候选和工具。
2. 默认 Docker 执行 Linux 镜像，非 root、cap-drop、no-new-privileges、network none、只读根、限定 tmpfs、CPU/内存/PID 和超时。仅挂载审查后的工作区快照/工作区和本次代码、输入、输出目录。无宿主命令回退。测试控制层可注入确定性的执行适配器，但其结果不得充当隔离证据。
3. 控制目录默认位于用户数据目录，禁止位于工作区。只读工作区复制过滤敏感路径和符号链接，写工作区必须明确授权且不包含控制目录。生成代码不接触控制层 Python 对象。
4. 内容寻址是产品存储机制；功能验收不执行 hash/checksum 比较。源码、Manifest、Review 用例与依赖版本统一固化，Review 执行真实期望输出用例，空测试不得准入。退出码与输出 schema 仅能证明结构。
5. 根任务、operation_id、run_id、parent_run_id 区分业务操作与尝试。运行前事务占位；重复操作不重放。崩溃遗留运行标记不确定而非自动重试。
6. 工作流由固定依赖和受限输入引用组成，控制层递归调度，无 eval 和动态命令拼接。依赖权限取闭包，父权限不得比子权限小。研究和模型请求经已配置宿主代理，适配器返回预算/来源数据；网页仅保存为数据。
7. 采用可注入 UTC 时钟进行生命周期验收，固定观察窗与计数周期分离。归档下线但被引用版本保留可供依赖调用；恢复新周期从零计数。
8. 本项目是单 Agent 本地运行时，无 A2A 协议；0.2.0 借鉴 A2ABreak v1.0 的01/06/08/10/11方案实施恶意调用者控制，协议专用项目按增量适用性说明排除。

## Risks / Trade-offs

### 2026-10-22 实施补齐

根调用持有项目写锁并使用一次性工作区，固定依赖在同一暂存区执行；完整执行及输出契约通过后才向用户工作区提交。外部写入不能回滚，因此候选自动注册不自动执行外部写入 Review，操作者必须显式复检。工作流子调用继承根任务的重试/缓存属性及绝对截止时间。

失败版本之后的修复按根任务计入 max_repairs；保留独立的创建总量上限。账单未知的预留及暂记费用保留至实际结算，不随普通聚合日志过期而丢弃。所有这些补齐使用本次新增的消费者行为用例验证；部署 Docker 边界和经济实验分别记录证据边界。

- [Docker 未运行或镜像未准备] → 结构化失败并保留真实环境阻塞，不回退宿主运行。
- [宿主适配器具有外网与模型权限] → 可信配置、只读网络白名单/SSRF 防护、预算、凭证按能力绑定，禁止动态提供 endpoint 或凭证。
- [无法自动证明研究事实] → 保留 unknown 事实状态及引用；结构通过不表示事实成立。
- [缺少真实账单与任务] → 交付采集器和严格对照报告，空数据返回 insufficient_data。

## Migration Plan

### 本机 MCP/hook 增量决策

沿用 Python/SQLite；真实 MCP 使用官方 Python SDK 2.x 的 MCPServer，不重造协议。SDK 为 integration 可选依赖，原 JSONL 入口保持原义。新 NativeSandbox 是显式选择的受信代码执行器，只接受操作者登记的完整 bundle 和固定入口，不接受模型自由 argv。它不提供 OS 隔离，也不承诺 Docker 的内存/PID/网络防护。首批工具只处理内联 JSON/CSV/文本，不获文件、网络、秘密授权。扩展程序由操作者提供独立案例和每次调用规则并登记；MCP 不开放审批、控制配置或宿主命令入口。

同一 stdio 连接由宿主签发固定期限和总调用上限的任务；MCP run 的具体 ID、版本、输入及业务键绑定操作。内置工具及自定义工具仍走 ControlPlane、Registry、Review、Ledger。hook 只读检索已审工具，匹配才返回短数据提示，失败或未匹配不阻断客户端。安装追加 ATR 配置且备份原文件，Codex 的 hook 信任由客户端 /hooks 管理。

继续应用 A2AB v1.0 的“工程解决方案/验收办法”：01 技能声明验证与委派准入（operator-only native 登记和独立用例）；06 并发状态版本与审批绑定（固定版本/操作幂等）；08 结构化授权请求与权限不放大（纯输入工具，不开放任意宿主命令）；10 委派环路检测与全链预算（宿主连接身份、调用上限与持久预算）；11 中断任务租约与有界资源回收（期限、超时/取消与退出）。02/03/04/05/07/09 的协议条件仍不具备，见 docs/security-hardening.md 全部11项增量评估；本机进程权限不等于隔离权限。

### 2026-10-22 恶意 Agent 控制增量

信任边界：操作者/宿主 Python 与控制目录可信；Agent JSON、工具程序、Manifest checks、网页和工具输出不可信。签发接口不进入五接口，宿主凭证不进入模型参数或工作区；同用户任意宿主 shell/控制目录写权限不在 ATR 能隔离的边界内。

可信控制层生成不可猜测任务 ID/凭证，持久化凭证摘要、绝对期限及总调用/创建/费用限额。所有调用认证宿主绑定上下文，拒绝 Agent 换 ID；预留费用同时约束根任务和实例持久总预算，子工作流/Review 不可重置预算。旧数据库保留历史事实，但旧任务与自拟 Review 不自动取得新授权。

宿主签发操作许可，绑定任务、业务键、固定版本/代码、参数、权限和期限；模型只可复用已发许可。任务允许读取的路径独立于允许创建/更新/删除路径，工作区快照只暴露获准读取内容，提交前核对全部变更操作。网络代理只执行已固定参数的请求，不把 host 白名单当作数据用途授权。

独立验收规则由宿主提供，绑定完整程序与环境；Manifest checks 只作为建议。Review 使用可信案例，单次操作还必须符合宿主结果与文件效果规则，检查发生在工作区发布之前。规则不能证明任意程序绝对无后门，未被规则覆盖的业务事实保持未知；工具输出始终标记不可信。

状态控制采用条件更新，旧版本失败不得改动其他活跃版本。关闭先停止接收并持久取消本实例所有未完成调用，排队任务终结，活动同步/异步调用退出后再关闭存储。

应用 A2ABreak v1.0 的“工程解决方案/验收办法”：A2AB-01 技能声明验证与委派准入（独立验收）、A2AB-06 并发状态版本与审批绑定（许可和回退原子校验）、A2AB-08 结构化授权请求与权限不放大（任务/资源/参数授权）、A2AB-10 委派环路检测与全链预算（可信根身份及聚合预算）、A2AB-11 中断任务租约与有界资源回收（固定期限和退出）。知识库入口 main/engineering/security/a2abreak/a2-abreak-多-agent-安全基线与-11-项方案索引。02 无 Agent Card，03 无多租户共享上下文服务，04 无 SSE，05 无分块流，07 无 Webhook，09 无多跳凭据；协议专用验收不适用，05 内容一致性不能证明语义真实。方案为本地工程建议，实际通过范围在安全交付文档记录。

uv sync 建立本地环境；docker build 构建运行镜像；CLI init 创建独立控制目录；按示例创建、Review、执行工具。关闭动态执行可立即回到受控 Direct；旧版本通过事务切换恢复。数据库使用 schema_version 顺序迁移，未知版本拒绝打开。
